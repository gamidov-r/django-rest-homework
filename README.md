## пример включения CI/CD:
### для этого потребуется создать ниже приведенные ключи в github secret actions
### название базы данных: ```DB_NAME```
### пароль от базы данных: ```DB_PASSWORD```
### путь к проекту на сервере```DEPLOY_DIR```
### секретный ключ: ```SECRET_KEY```
### IP адрес сервера проекта: ```SERVER_IP```
### порт сервера для доступа по ssh (по умлочанию 22): ```SERVER_PORT```
### публичный ключ доступа к серверу по ssh: ```SSH_KEY```
### имя пользователя сервера для входа по ssh: ```SSH_USER```
### публичный ключ доступа от сервиса stripe: ```STRIPE_PUBLIC_KEY```
### секретный ключ доступа от сервиса stripe:```STRIPE_SECRET_KEY```
### запуште файл .github.workflows/deply.yml, он отобразится Actions под названием ```Deploy with Rsync```
> rsync используется для того, чтобы избежать регистрации на docker hub

``` GET http://127.0.0.1:8000/users/users/```

``` GET http://127.0.0.1:8000/users/users/2/```
### Список всех транзакций:
``` GET http://127.0.0.1:8000/users/payments/```
### Конкретная транзакция с id 4:
``` GET http://127.0.0.1:8000/users/payments/4/```
### Список всех курсов:
``` GET http://127.0.0.1:8000/materials/courses/```
### Информация по конкретному курсу с id 13
``` GET http://127.0.0.1:8000/materials/courses/13/```
> в том числе выводятся уроки в данном курсе и кол-во уроков в курсе (задание 4)
### Список всех уроков:
``` GET http://127.0.0.1:8000/materials/lessons/```
### Информация по конкретному уроку с id 5
``` GET http://127.0.0.1:8000/materials/lessons/5/```
### так-же доступны POST запросы для создания, обновления и удаления всех объектов (пользователи, транзакции, уроки, курсы)
### Разберем на примере уроков:
### удаление урока с id 5
``` POST http://127.0.0.1:8000/materials/lessons/5/delete/```
### создание урока
``` POST http://127.0.0.1:8000/materials/lessons/create/```
### и запрос в формате JSON
```
{
    "name": "12 урок",
    "description": "описание к 12му уроку",
    "preview": null,

    "course": 13

```
